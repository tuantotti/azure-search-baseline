# Azure AI Search SDK experiment API

A FastAPI service for deployment inside UAT. Your local browser calls UAT Swagger;
the server connects to Azure. Python 3.12. Version 3 replaces the previous custom
REST client with the async Azure SDK and restores FastAPI's default documentation.

## Changes requested

- Azure `SearchClient` and `SearchIndexClient` from azure-search-documents **12.1.0b2** (preview; agentic retrieval support).
- `AsyncAzureOpenAI` or `AsyncOpenAI` for server-side embeddings, selected by environment.
- Native GenAI Prompt summarization attached to an existing Azure indexer.
- Thin routers, typed schemas, independent services, repository/provider protocols,
  and SDK adapters composed in one lifecycle-managed container.
- Removed TEST_API_KEY, APIKeyHeader, authorize dependencies, and X-API-Key checks.
- Removed the custom Swagger route, StaticFiles mount and swagger-ui-bundle dependency.
- Default `/docs`, `/redoc`, `/openapi.json`. OpenAPI is generated by FastAPI;
  there is no artificial version override.
- Removed the old monolithic REST/CLI implementation and stale tests/configuration.
  Baseline schema, document metrics and synthetic sample data remain.
- Removed custom index-prefix/write-enable gates. Azure permissions determine
  whether an operation succeeds. Index creation still does not overwrite existing indexes.

## Authentication: which key is required?

| Connection              | Configuration                                                |
| ----------------------- | ------------------------------------------------------------ |
| Browser → FastAPI      | No API authorization header, per your request                |
| FastAPI → Azure Search | AZURE_SEARCH_API_KEY, or DefaultAzureCredential when omitted |
| FastAPI → Azure OpenAI | AZURE_OPENAI_API_KEY, or Entra credential when omitted       |

The deleted TEST_API_KEY was an application-level gate. It was never an Azure
credential. Azure Search still requires service authentication. For key auth,
search can use a query key; creating indexes/writing documents requires an admin
key. For managed identity, assign the relevant data-plane roles (Search Index
Data Reader for queries, Search Index Data Contributor for documents, Search
Service Contributor for index management). Azure OpenAI also needs its appropriate
role when using Entra identity. No credentials belong in request JSON.

This unauthenticated API allows reachable callers to use the configured Azure
permissions. Deploy it within your controlled UAT network/ingress.

An optional `X-MS-Query-Source-Authorization` is still available on search endpoints
for native document-permission experiments. It is not your API's authentication
and is unnecessary for ordinary search. It only has effect with Azure-supported
source/index/API configurations. Supplying it alone does not enable ACL enforcement.
Custom ACL fields and filters remain available as ordinary index/query data.

## Deploy

Copy `.env.example` to `.env` and configure your Azure endpoints and credentials.
For managed identity, remove the API-key variables. Embedding configuration is
optional if using only raw/SDK searches with existing vectors or index vectorizers.

```bash
docker compose up --build -d
```

Or run in UAT directly:

```bash
python -m pip install -r requirements.txt
python -m uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8888
```

Open `http://UAT-HOST:8888/docs`. Use **Try it out** directly: there is no Authorize
step. UAT needs DNS/network access to Azure, including any private endpoints.
The default Swagger page loads FastAPI's standard CDN assets, so the browser must
be able to reach that CDN. No custom Swagger files are shipped.
Set ROOT_PATH when an ingress strips a URL prefix. Build the Docker image in CI
and deploy the image if UAT cannot download Python packages. Set your ingress
request timeout high enough for comparisons with multiple SDK calls.

## Embedding provider

`EMBEDDING_PROVIDER` selects one provider for `/embeddings`, document embedding,
query embedding, and comparison experiments. It defaults to `azure_openai`.

| Provider         | Required configuration                                           | Authentication                                                      |
| ---------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------- |
| `azure_openai` | `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_EMBEDDING_DEPLOYMENT` | `AZURE_OPENAI_API_KEY`, or application `DefaultAzureCredential` |
| `openai`       | `OPENAI_EMBEDDING_MODEL`, `OPENAI_API_KEY`                   | Public OpenAI API key                                               |

For public OpenAI, for example:

```dotenv
EMBEDDING_PROVIDER=openai
OPENAI_API_KEY=YOUR-OPENAI-KEY
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
```

Keep secrets in server configuration. Embedding configuration is optional until
an operation needs a vector; incomplete configuration returns HTTP 503 for that
operation and does not prevent BM25 or raw search. Both providers request float
vectors and use `REQUEST_TIMEOUT_SECONDS` and `AZURE_RETRY_TOTAL`.
Responses retain the legacy `{elapsed_ms, azure}` envelope for compatibility;
`azure` contains the embedding API response even when using public OpenAI.

Use the same embedding model for documents and queries. When changing provider
or model, re-embed documents and use an index with matching vector dimensions;
equal dimensions alone do not make different models compatible. Existing index
vectorizers are configured independently of this Python provider setting.

## Native LLM document summaries

The summary setup extends an **existing Azure indexer** that produces one record
per document and exposes `/document/content`. It clones the indexer's attached
skillset under a new name, preserves its existing skills/configuration, and adds
`#Microsoft.Skills.Custom.ChatCompletionSkill` named `document-summary`. An indexer
without skills gets a new summary-only skillset. Chunk index projections are
rejected by this document-level workflow.

Configure `AZURE_OPENAI_ENDPOINT` and `AZURE_OPENAI_CHAT_DEPLOYMENT` for a chat
completions deployment. The embedding-provider setting does not select the summary
LLM. `AZURE_OPENAI_CHAT_MODEL` remains required only by agentic knowledge-base
creation. `OPENAI_API_VERSION` is used in the skill's chat endpoint;
`AZURE_SEARCH_SKILL_API_VERSION` defaults to `2026-04-01` for skill/indexer
management, independently of the search and agentic versions.

If `AZURE_OPENAI_API_KEY` is configured, the skill uses that key. Otherwise,
enable the **Search service's system-assigned managed identity**, grant it
Cognitive Services OpenAI User on the Azure OpenAI resource, and ensure network
connectivity from Search to the model endpoint. The application identity used
for embeddings is a separate connection. The Search credential also needs index,
skillset, and indexer management permissions.

1. `POST /indexers/YOUR-INDEXER/summary-skill` with
   [examples/11-summary-skill.json](examples/11-summary-skill.json). Supply an unused
   `skillset_name`; `prompt` is optional and defaults to concise factual summarization.
2. Setup adds a searchable/retrievable `summary` string field if missing and maps
   `/document/summary` into it. Existing incompatible fields/mappings are rejected.
   Index and indexer updates require matching ETags; concurrent changes return 412.
3. For previously indexed documents, call `POST /indexers/YOUR-INDEXER/reset`,
   then `POST /indexers/YOUR-INDEXER/run` (202 Accepted).
4. Poll `GET /indexers/YOUR-INDEXER/status`; inspect `lastResult`, errors, warnings,
   and item counts. Once indexing completes, retrieve/search the `summary` field
   through the existing search endpoints.

Setup does not invoke run or reset. Existing indexer schedules remain active, so
a scheduled run can process the new skill after attachment. Direct JSON document
uploads continue using the Python pipeline and do not execute native skills.
Summaries do not change the configured document embeddings or semantic fields.
Whole-document text must fit the chat model's context window; inspect indexer
warnings/errors for oversized input, timeouts, and model throttling.

Setup never overwrites another skillset. If Azure returns masked or unavailable
credentials in the original skillset, restore its credentials or configure managed
identity before cloning. Credentials in selected presets being replaced do not need
to be copied. Resource writes are sequential, not transactional: a
failure reports completed steps, leaves created resources in place, and requires
inspection before retrying with a fresh skillset name. Model keys are omitted
from setup responses. Do not run setup concurrently with other pipeline changes.

The pinned SDK has a stable-version validation bug in its indexer-update helper.
This adapter uses the public SDK request pipeline for that conditional PUT;
other management calls use the typed SDK methods.

References: [GenAI Prompt skill](https://learn.microsoft.com/en-us/azure/search/cognitive-search-skill-genai-prompt),
[OpenAI embeddings](https://developers.openai.com/api/reference/python/resources/embeddings/methods/create).

## Skill experiments in Swagger

Use `POST /indexers/{indexer_name}/skills` to choose one or more text presets.
Start with an existing document-level indexer that exposes `/document/content`.
You can override each preset's `input_path` with another document-level text node;
wildcard/chunk paths are reserved for advanced skillsets.

| `kind` | Output fields | Request example |
| --- | --- | --- |
| `classification` | `document_category` | [12-classification-skills.json](examples/12-classification-skills.json) |
| `entities` | `entities_persons`, `entities_organizations`, `entities_locations`, etc. | [13-entity-skills.json](examples/13-entity-skills.json) |
| `key_phrases` | `key_phrases` | [14-key-phrase-skills.json](examples/14-key-phrase-skills.json) |
| `language_detection` | `detected_language` | [15-language-skills.json](examples/15-language-skills.json) |
| `sentiment` | `document_sentiment` | [16-sentiment-skills.json](examples/16-sentiment-skills.json) |
| `summary` | `summary` | [17-summary-skills.json](examples/17-summary-skills.json) |

All outputs are searchable and retrievable. Entities and key phrases are string
collections; the other outputs are strings. Every preset except summary also
creates filterable/facetable fields. Summary keeps its existing schema for
compatibility. Existing `classification` metadata is preserved.

Classification uses the Azure chat deployment to choose exactly one label from
your `categories`. Labels must be nonempty and unique; `instruction` is optional.
Include `Other` and explain when to use it if you want a fallback label. The
prompt requests an exact label, but the indexer does not validate LLM compliance:
inspect returned values/facets before treating them as trusted categories.
Only classification and summary require the Azure chat configuration.

Entity extraction uses **Entity Recognition V3**. It defaults to `Person`,
`Organization`, and `Location`, and supports all 14 documented category names
shown in Swagger. `minimum_precision` ranges from 0 to 1. Output field suffixes
use Azure output names, for example `entities_dateTimes` and `entities_emails`.
Language-aware presets use their own `language_code`, defaulting to `en`.
Selecting language detection does not automatically wire it into other skills.
Sentiment stores the document label; sentence details, confidence scores, and
opinion mining can be configured through advanced JSON.

### Run a combined experiment

1. Load the three synthetic `.txt` files in [data/skill-experiments](data/skill-experiments)
   into your existing indexer's data source, for example your Blob container.
   These are raw source files, not `/documents` API payloads. Ensure your existing
   source/indexer maps its document key and extracted text appropriately.
2. In `/docs`, POST [18-combined-skills.json](examples/18-combined-skills.json) to
   `/indexers/YOUR-INDEXER/skills`. The API clones the current skillset, adds fields
   and output mappings, and attaches the new skillset. It does not run the indexer.
3. POST `/indexers/YOUR-INDEXER/reset`, then POST `/indexers/YOUR-INDEXER/run`.
4. GET `/indexers/YOUR-INDEXER/status` until `lastResult.status` indicates success;
   inspect warnings, errors, and item counts. Run acceptance alone does not prove
   enrichment succeeded.
5. POST [21-search-enrichments.json](examples/21-search-enrichments.json) to
   `/indexes/YOUR-INDEX/search`. It retrieves the combined output fields, filters
   by category, and facets classification, language, and sentiment. Remove the
   filter initially to inspect all results; model outputs are not guaranteed.

Additional raw search filters you can try:

```json
{
  "search": "*",
  "select": "content,entities_organizations,key_phrases,document_sentiment",
  "filter": "entities_organizations/any(x: x eq 'Contoso Labs')",
  "facets": ["document_sentiment", "key_phrases"],
  "top": 10
}
```

Use only output fields created by your selected presets. Repeated experiments
require a **fresh skillset name** each time. Selected app-managed skills are
replaced in the clone, while other skills remain. Reserved preset names carry
an ownership marker and recognizable outputs; unrelated skills with those names
are rejected. The previous summary preset is recognized for upgrades.

Index fields from earlier experiments remain. When you narrow entity categories,
obsolete app-managed output mappings are removed, while fields remain in the
schema. Reset/rerun to refresh current outputs; removing a mapping does not
promise to clear values already stored. Use a fresh test index/data pipeline
when you need completely isolated results. Existing schedules remain active.

### Built-in skill billing

Optionally configure:

```dotenv
AZURE_AI_SERVICES_ENDPOINT=https://YOUR-RESOURCE.services.ai.azure.com
# AZURE_AI_SERVICES_KEY=YOUR-AI-SERVICES-KEY
```

With a key, the skillset uses `AIServicesByKey`. Without a key, the configured
endpoint uses `AIServicesByIdentity` with the **Search service's system-assigned
managed identity**; enable it and grant Cognitive Services User on the billing
resource. This resource is separate from the Azure OpenAI chat deployment.
A key without an endpoint is rejected when configuring skills.

A configured endpoint replaces the billing connection in new or cloned
skillsets. Otherwise, existing billing configuration is preserved. If neither
exists, Azure's small free allowance applies (currently up to 20 transactions
per index per day for applicable built-in skills). Splitting documents and
running multiple skills can consume multiple transactions; inspect your Azure
usage. LLM calls are billed separately and do not use this allowance.

### Advanced skillset JSON

| Operation | Endpoint |
| --- | --- |
| Create a new definition; never overwrite | `POST /skillsets/{skillset_name}` |
| Inspect a definition with credentials removed | `GET /skillsets/{skillset_name}` |
| Attach an existing definition | `POST /indexers/{indexer_name}/skillset` |

POST [19-custom-entity-skillset.json](examples/19-custom-entity-skillset.json) to
`/skillsets/uat-custom-entities-v1`. Then POST
[20-attach-custom-entity-skillset.json](examples/20-attach-custom-entity-skillset.json)
to `/indexers/YOUR-INDEXER/skillset`. Reset, run, and inspect status as above.
The example recognizes Azure AI Search and Amazon Bedrock aliases. Search with:

```json
{
  "search": "*",
  "select": "content,custom_entity_names",
  "filter": "custom_entity_names/any(x: x eq 'Azure AI Search')",
  "facets": ["custom_entity_names"]
}
```

Advanced definitions use Azure wire names, including `@odata.type`, `inputs`,
`outputs`, and skill-specific parameters. Unknown properties are forwarded
unchanged for the configured `AZURE_SEARCH_SKILL_API_VERSION`; Azure validates
whether they are supported. Credentials and custom authentication headers are
removed from inspection responses. Responses containing redacted credentials
cannot be blindly reused as complete definitions.

Attachment explicitly switches the indexer to the specified skillset; it does
not clone or merge that skillset's skills. Optional `fields` and
`output_field_mappings` add compatible index fields and indexer mappings without
replacing existing definitions. Conflicting fields/mappings fail before writes.
For projection-based skillsets, configure the target schema/projections yourself
and attach with just `skillset_name`; automatic field/mapping additions reject
index projections. Skills needing chunks, images, document extraction, external
Web APIs, or other services require the corresponding existing indexer and
service configuration. No data sources or external services are provisioned.

| POST   | /indexes/{index_name}/search/sdk                | SearchClient.search, typed SDK arguments      |

| POST   | /knowledge-sources/{source_name}                | SearchIndexClient.create_knowledge_source     |
| GET    | /knowledge-sources/{source_name}                | SearchIndexClient.get_knowledge_source        |

| POST   | /knowledge-bases/{knowledge_base_name}/retrieve | KnowledgeBaseRetrievalClient.retrieve         |

Search/index operations support an `api_version` query override. The pinned SDK
and selected REST version must support the feature; changing the version cannot
add missing SDK model fields. Custom index schemas use SDK-supported properties.
The raw search endpoint is the extension point for newer Search POST fields.
It still uses the public SDK pipeline for credentials, retries and HTTP handling;
there is no hand-written REST transport or request-time endpoint override.

## Sample requests for every API

Run these commands from the repository root against the running service. Swagger is
available at `http://localhost:8888/docs`; the examples below match its live
`/openapi.json`. Use `localhost` or `127.0.0.1` as the client address; `0.0.0.0`
is the server bind address.

```bash
BASE_URL=http://localhost:8888
API_VERSION=2025-09-01
BASIC_INDEX=readme-basic-20261019
INDEX=readme-baseline-20261019
```

Use fresh index names when repeating the creation calls: creation does not overwrite
an existing index. The names above were created during the live checks below and
contain synthetic sample data. There is no index-deletion endpoint in this API.

All Search examples explicitly use `api_version=2025-09-01`. The baseline schema
includes an index `description`, which Azure rejects with `2024-07-01`. Set
`AZURE_SEARCH_API_VERSION=2025-09-01` in `.env` and restart the server if you want
to omit the override. `2025-05-01` is not a valid Search API version; the similarly
named preview is `2025-05-01-preview`. `/embeddings` uses the separately configured
`OPENAI_API_VERSION` and Azure OpenAI deployment.

Create the baseline index before its document and search calls. The configured
embedding deployment returned **1536 dimensions** during testing. Adjust the
baseline dimensions if your deployment returns a different length. The basic
index is a separate minimal example; the remaining samples use the baseline index.

### 1. Health — `GET /health`

Returns `{"status":"ok"}`. This checks process liveness only.

```bash
curl -sS \
  "$BASE_URL/health"
```

### 2. Generate embeddings — `POST /embeddings`

Requires the Azure OpenAI endpoint, deployment and credentials. Inspect
`azure.data[0].embedding` to determine the vector length.

```bash
curl -sS -X POST \
  "$BASE_URL/embeddings" \
  -H 'Content-Type: application/json' \
  -d '{"input":["test embedding dimensions"]}'
```

### 3. Create a custom index — `POST /indexes/{index_name}`

Provide a nonempty `fields` array with a key field. `{}` is not a complete
index definition. The URL supplies the index name; if the body includes `name`,
it must match the URL. A successful creation returns HTTP `201`.

```bash
curl -sS -X POST \
  "$BASE_URL/indexes/$BASIC_INDEX?api_version=$API_VERSION" \
  -H 'Content-Type: application/json' \
  -d '{
  "fields": [
    {
      "name": "id",
      "type": "Edm.String",
      "key": true
    },
    {
      "name": "content",
      "type": "Edm.String",
      "searchable": true
    }
  ]
}'
```

### 4. Read an index — `GET /indexes/{index_name}`

Returns the schema in `azure`; also verifies Azure Search connectivity.

```bash
curl -sS \
  "$BASE_URL/indexes/$BASIC_INDEX?api_version=$API_VERSION"
```

### 5. Create the baseline index — `POST /indexes/{index_name}/baseline-schema`

Creates text, metadata, ACL, vector and semantic fields. Returns HTTP `201`.

```bash
curl -sS -X POST \
  "$BASE_URL/indexes/$INDEX/baseline-schema?api_version=$API_VERSION" \
  -H 'Content-Type: application/json' \
  -d '{
  "dimensions": 1536,
  "description": "README API smoke test"
}'
```

### 6. Index documents — `POST /indexes/{index_name}/documents`

Accepts Azure batch actions: `upload`, `merge`, `mergeOrUpload`, or `delete`.
This sample uploads a text document without generating a vector. Check
`all_succeeded` and every entry in `azure.value`, even after HTTP `200`.

```bash
curl -sS -X POST \
  "$BASE_URL/indexes/$INDEX/documents?api_version=$API_VERSION" \
  -H 'Content-Type: application/json' \
  -d '{
  "value": [
    {
      "@search.action": "upload",
      "chunk_id": "readme-chunk-1",
      "document_id": "readme-leave",
      "title": "Annual leave",
      "content": "Employees have 12 days of annual leave. Request leave through the HR portal.",
      "is_public": true,
      "domain": "hr"
    }
  ]
}'
```

### 7. Embed and index chunks — `POST /indexes/{index_name}/documents/embed`

Generates vectors with the configured Azure OpenAI deployment, then writes the
chunks to Search. Its embedding dimensions must match the baseline index. Check
`all_succeeded` and each document status.

```bash
curl -sS -X POST \
  "$BASE_URL/indexes/$INDEX/documents/embed?api_version=$API_VERSION" \
  -H 'Content-Type: application/json' \
  -d '{
  "documents": [
    {
      "chunk_id": "readme-chunk-2",
      "document_id": "readme-leave",
      "title": "Request annual leave",
      "content": "Submit annual leave requests through the HR portal for manager approval.",
      "domain": "hr",
      "source": "synthetic",
      "document_type": "policy",
      "classification": "public",
      "source_uri": "https://example.invalid/readme-leave",
      "page_start": 1,
      "is_public": true,
      "allowed_group_ids": []
    }
  ]
}'
```

### 8. Raw REST search — `POST /indexes/{index_name}/search`

Uses Azure REST naming: `search`, `count`, and comma-separated `select`.
Results are returned in `azure.value`.

```bash
curl -sS -X POST \
  "$BASE_URL/indexes/$INDEX/search?api_version=$API_VERSION" \
  -H 'Content-Type: application/json' \
  -d '{
  "search": "annual leave",
  "top": 10,
  "count": true,
  "filter": "is_public eq true",
  "select": "chunk_id,document_id,title,content"
}'
```

### 9. Typed SDK search — `POST /indexes/{index_name}/search/sdk`

Uses SDK naming: `search_text`, `include_total_count`, and a `select` array.

```bash
curl -sS -X POST \
  "$BASE_URL/indexes/$INDEX/search/sdk?api_version=$API_VERSION" \
  -H 'Content-Type: application/json' \
  -d '{
  "search_text": "annual leave",
  "top": 10,
  "include_total_count": true,
  "filter": "is_public eq true",
  "select": [
    "chunk_id",
    "document_id",
    "title",
    "content"
  ]
}'
```

### 10. Search from query text — `POST /indexes/{index_name}/search/text`

This hybrid example embeds the query and combines text and vector retrieval.
Use `mode: "bm25"` for text-only retrieval without Azure OpenAI. Other modes are
`vector` and `hybrid_semantic`; semantic mode requires semantic ranker availability.

```bash
curl -sS -X POST \
  "$BASE_URL/indexes/$INDEX/search/text?api_version=$API_VERSION" \
  -H 'Content-Type: application/json' \
  -d '{
  "query": "How do I request annual leave?",
  "mode": "hybrid",
  "k": 50,
  "parameters": {
    "top": 10,
    "filter": "is_public eq true",
    "select": [
      "chunk_id",
      "document_id",
      "title",
      "content"
    ]
  }
}'
```

### 11. Compare retrieval modes — `POST /indexes/{index_name}/experiments/compare`

Runs BM25, vector and hybrid retrieval with one shared query embedding.
`qrels` maps document IDs to relevance grades from 0 to 3. Comparison requires
`parameters.top` from 10 to 50 and no nonzero `skip`. Add `hybrid_semantic` only
when semantic ranker is available; use `k >= 50` for that mode.
The response contains `runs`, `mean_search_ms`, and `query_embedding_ms`.

```bash
curl -sS -X POST \
  "$BASE_URL/indexes/$INDEX/experiments/compare?api_version=$API_VERSION" \
  -H 'Content-Type: application/json' \
  -d '{
  "query": "How do I request annual leave?",
  "modes": [
    "bm25",
    "vector",
    "hybrid"
  ],
  "k": 50,
  "repeats": 1,
  "parameters": {
    "top": 10,
    "filter": "is_public eq true",
    "select": [
      "chunk_id",
      "document_id",
      "title",
      "content"
    ]
  },
  "qrels": {
    "readme-leave": 3
  }
}'
```

## Agentic retrieval with the Azure SDK

Agentic retrieval uses Azure Search to plan subqueries with a chat model and
return grounding context. It uses the async `SearchIndexClient` and
`KnowledgeBaseRetrievalClient` from **azure-search-documents 12.1.0b2**. Agentic
operations use **2026-08-01-preview**, separately from ordinary index/search calls.
The SDK migration uses model mapping constructors and `as_dict()`; existing API
response envelopes remain unchanged.

### Configure Azure and the server

1. Use a Search service/region supporting agentic retrieval and enable semantic
   ranker. Populate an index with searchable content and a semantic configuration.
   The existing baseline endpoint creates `semantic-config`; the minimal basic
   index example does not. Sources do not modify the index schema.
2. Deploy a supported Azure OpenAI chat model. Supply its actual deployment name
   and model name below; the embedding deployment cannot serve as the planner.
3. Configure `.env` and restart the server (or rebuild the Docker image):

```dotenv
AZURE_SEARCH_API_VERSION=2025-09-01
AZURE_SEARCH_AGENTIC_API_VERSION=2026-08-01-preview
AZURE_OPENAI_CHAT_DEPLOYMENT=YOUR-CHAT-DEPLOYMENT
AZURE_OPENAI_CHAT_MODEL=gpt-4.1-mini
```

The chat connection reuses `AZURE_OPENAI_ENDPOINT` and, when supplied,
`AZURE_OPENAI_API_KEY`. These credentials are stored in the Azure knowledge-base
model definition through the SDK and removed from this API's management responses.
Credentials are never accepted in the request JSON.

For keyless Search-to-OpenAI access, omit `AZURE_OPENAI_API_KEY`, enable the
Search service's system-assigned managed identity, and assign it **Cognitive
Services User** on the Azure OpenAI/Foundry resource. This identity is separate
from the API server's `DefaultAzureCredential`. The server still needs its own
OpenAI permissions if it also generates embeddings using Entra authentication.

Use a Search admin key or appropriate resource-management RBAC permissions for
creating/reading source and base definitions. Retrieval first reads the knowledge
base to resolve its sources, so its credential must also permit that read, in
addition to retrieval access. Existing Search authentication settings are reused.
Missing endpoint/chat deployment/model settings return `503` on base creation;
retrieving an existing configured base does not need those local chat settings.

### Request examples

Run from the repository root after creating/populating the baseline index. Source
and base creation are create-only; choose fresh names and update the sample JSON
when repeating the workflow. Existing resources are never silently overwritten.

```bash
BASE_URL=http://localhost:8888
SOURCE=readme-agentic-source
KNOWLEDGE_BASE=readme-agentic-base
```

Create a source linked to the existing index (`201`):

```bash
curl -sS -X POST "$BASE_URL/knowledge-sources/$SOURCE" \
  -H 'Content-Type: application/json' \
  --data-binary @examples/08-agentic-source.json
```

Read the source (`200`):

```bash
curl -sS "$BASE_URL/knowledge-sources/$SOURCE"
```

Create a knowledge base with low-effort LLM planning and extractive output (`201`):

```bash
curl -sS -X POST "$BASE_URL/knowledge-bases/$KNOWLEDGE_BASE" \
  -H 'Content-Type: application/json' \
  --data-binary @examples/09-agentic-base.json
```

Read the knowledge base (`200`, model credentials removed):

```bash
curl -sS "$BASE_URL/knowledge-bases/$KNOWLEDGE_BASE"
```

Retrieve grounding context (`200`):

```bash
curl -sS -X POST "$BASE_URL/knowledge-bases/$KNOWLEDGE_BASE/retrieve" \
  -H 'Content-Type: application/json' \
  --data-binary @examples/10-agentic-retrieve.json
```

Source creation accepts `index_name`, optional `description`,
`semantic_configuration_name`, `search_fields`, and `source_data_fields`. Only
retrievable fields should be requested as source data. Base creation accepts
`knowledge_source_names` and an optional `description`; its planner comes from
server configuration.

Retrieval accepts `messages` containing nonempty text `content` and `user` or
`assistant` roles. Include at least one user message. Send the conversation
history on every call; the server stores no conversation state. Optional
`knowledge_source_params` entries identify a `knowledge_source_name` and an OData
`filter_add_on`. Unknown source names are rejected. Filters only narrow the named
source, not other sources in the base. Omit this list to query without extra
filters. References, reference source data, and activity are requested for every
source regardless of whether it has a filter.

The response retains `{ "elapsed_ms": ..., "azure": ... }`.
`azure.response` contains extractive context, `azure.references` links it to source
data, and `azure.activity` describes retrieval work. The server performs no local
query embedding or answer synthesis. Empty reference lists are valid when nothing
matches. Elapsed time includes the knowledge-base lookup and retrieval.

Optional `X-MS-Query-Source-Authorization` is passed through the SDK for Azure
native document permissions. It only enforces permissions on appropriately
configured Azure sources/indexes; ordinary caller-provided filters are not an
authorization policy. Agentic operations use the dedicated version setting and
have no per-request `api_version` override.

Resource conflicts return `409`; invalid request shapes return `422`. Azure errors
use the existing error mapping, including `502` for server credential failures.
This version does not expose updates, deletion, external sources, streaming, or
answer synthesis. The API itself remains unauthenticated as described above.

## Request naming: REST versus SDK

The raw `/search` endpoint retains Azure REST camelCase and arbitrary additional
fields. For example:

```json
{
  "search": "nghỉ phép",
  "top": 10,
  "count": true,
  "filter": "is_public eq true",
  "select": "chunk_id,document_id,title,content"
}
```

`/search/sdk` uses the SDK's snake_case options and arrays:

```json
{
  "search_text": "nghỉ phép",
  "top": 10,
  "include_total_count": true,
  "filter": "is_public eq true",
  "select": ["chunk_id", "document_id", "title", "content"]
}
```

For `/search/text`, Azure query embeddings are generated in UAT:

```json
{
  "query": "Tôi cần làm gì để xin nghỉ phép?",
  "mode": "hybrid",
  "vector_field": "content_vector",
  "k": 50,
  "parameters": {
    "top": 10,
    "filter": "is_public eq true",
    "select": ["chunk_id", "document_id", "title", "content"]
  }
}
```

Available modes: bm25, vector, hybrid, hybrid_semantic. BM25 requires no embedding
configuration. Use the same embedding model/dimensions for index and queries.
The `parameters` object now uses SDK naming: for example `search_fields` and
`select` arrays, not comma-separated REST strings. Controlled mode parameters
(search_text, vector_queries, query_type, etc.) are not accepted in convenience
requests; use /search/sdk or /search for fully manual queries.

For raw vectors in `/search/sdk`, use:

```json
{
  "top": 10,
  "vector_filter_mode": "preFilter",
  "vector_queries": [
    {"vector": [0.1, 0.2], "fields": "content_vector", "k_nearest_neighbors": 50}
  ]
}
```

The two-element vector is illustrative: replace it with the full vector matching
your field dimensions. Alternatively provide `text` instead of `vector` when the
index has an Azure query vectorizer. The SDK builds VectorizedQuery or
VectorizableTextQuery accordingly. Pure vector queries omit search_text.

## Structure and responsibilities

| Module                    | Responsibility                                            |
| ------------------------- | --------------------------------------------------------- |
| app/main.py               | Application factory, lifecycle registration, HTTP logging |
| app/container.py          | Compose dependencies and close async resources            |
| app/api/routes/           | Thin HTTP endpoints                                       |
| app/api/dependencies.py   | FastAPI dependency injection                              |
| app/api/error_handlers.py | Central exception handling                                |
| app/schemas/              | Pydantic v2 request/response contracts                    |
| app/services/             | Retrieval, comparison, indexing workflows                 |
| app/ports.py              | Repository and embedding-provider interfaces              |
| app/infrastructure/       | Azure SDK implementations                                 |
| app/domain/               | Pure index schema and metric functions                    |
| app/core/                 | Settings, logging, application exceptions                 |

The services depend on small interfaces. Tests replace those interfaces without
changing business logic. SDK adapters own serialization and Azure I/O. HTTP
exceptions stay out of business services. Async HTTP sessions are reused and
closed on shutdown; SDK clients are scoped to operations. Azure/OpenAI retry counts
and per-request timeouts are configured. Timing includes SDK retries and result
pagination, excludes query embedding (reported separately).

## Experiments and limits

Comparison evaluates one query per request. It reuses one query embedding and
randomizes mode order with a fixed seed. Optional qrels are document IDs mapped
to grades 0–3, and must reflect the supplied filter/permissions. Recall measures
relevant documents represented in the first top chunks. MRR/nDCG deduplicate
documents within the first 10 chunks; duplicates do not inflate recall. Empty
qrels yield null scores. It is not an answerability detector or load test.

Raw searches preserve Azure JSON. Typed SDK searches return documents, count,
facets, answers and coverage when present. They do not promise arbitrary future
response extensions; use /search for exact REST-level experiments. Semantic
fallback is rejected for the baseline modes. No automatic ACL filter is injected.
Azure 401/403 errors become HTTP 502 because they concern server credentials;
validation/conflict/throttle errors retain their relevant status. Request bodies,
keys and tokens are not logged. Azure validation messages are returned for debugging.

## ComplexWebQuestions benchmark

The benchmark in `experiments/` calls this app's HTTP API exclusively. It indexes the
local training Q&A records and compares hybrid, hybrid with semantic reranking, and
Azure Agentic Retrieval on a seeded, proportionally stratified dev sample. This is
**Q&A retrieval using shared answer IDs as proxy relevance**, not evidence relevance
or generated-answer accuracy. Gold dev answers are used only for local evaluation.

Install `requirements-dev.txt`, start the updated app, then run:

```bash
.venv/bin/python -m experiments.main --run-live \
  --base-url http://127.0.0.1:8888 \
  --question-limit 100 --repeats 3 --seed 42
```

`AZURE_OPENAI_ENDPOINT` and `AZURE_OPENAI_EMBEDDING_DEPLOYMENT` are read from the
process environment or `.env`; override with `--vectorizer-endpoint` and
`--vectorizer-deployment`. Only these nonsecret values are saved. The model is
inferred from `/embeddings` for recognized Azure model names; otherwise provide
`--vectorizer-model` (or `CWQ_VECTORIZER_MODEL`). The selected Python embedding model
and Azure vectorizer deployment must produce compatible vectors. The Search
service's system-assigned managed identity must be enabled and authorized to invoke
that Azure OpenAI deployment. The benchmark uses no API key in its vectorizer.
Agentic retrieval additionally needs the app's existing Azure chat configuration.
The running app must expose the new optional `max_output_documents` request field;
restart an older server before running the benchmark.

Default execution indexes all 27,734 local training records. For a small live
workflow check use `--train-limit 32 --question-limit 2 --repeats 1`; this is a smoke
experiment with a restricted corpus, not a representative quality comparison.
`--question-limit 0` selects every dev question. No files are downloaded. Native
CWQ `question` and readable training answer labels form the indexed text; aliases
supply missing canonical labels. Machine questions and SPARQL are excluded.

Each run creates fresh index, knowledge-source and knowledge-base names. It probes
embeddings, creates a semantic/vector index, validates managed-identity text
vectorization with one record, uploads embeddings in batches of at most 32, and
polls count plus every document key before measuring. Existing resources are never
overwritten or deleted. Setup/ingestion transient failures have bounded retries;
measured retrieval calls are not retried. Processing is sequential, with one
excluded warm-up per method, three repetitions, and seeded randomized method order.
All methods use the same base-question and normalized-question exclusions and
request up to 50 documents; hybrid uses 50 vector candidates. Equal output limits
do not equalize agentic internal work.

Artifacts live under ignored `artifacts/cwq/<run-id>/`: manifest with hashes and
sampled IDs, progress, incremental JSONL results (including agentic activity),
per-query CSV, summary JSON and Markdown. The summary reports answer Hit/Coverage/
All-Answers-Hit and proxy document Recall/MRR/nDCG at 1, 5 and 10; corpus answer
coverage; successful and failed operations; HTTP latency mean/median/p90/p95;
server timings; available planner tokens; type breakdowns; and paired-success
quality differences. Uncovered questions remain sampled; document metrics without
relevant eligible records are undefined. Failure-adjusted Answer Hit@10 is reported
alongside success-only quality. HTTP latency includes query embedding.

Resume an interrupted run with **the same arguments**, adding
`--run-id <existing-id> --resume`. Dataset hashes, sampled IDs, configuration and
embedding identity must match. Completed attempts, including failures, are retained;
start a new run to repeat them. A crash during a resource creation leaves an
ambiguous-write checkpoint: inspect that run's resources and start a fresh run,
rather than risking adoption of another resource. Partial results are saved and
incomplete runs return a nonzero exit status. Resources remain available for
inspection and must be cleaned up explicitly by the operator.

### Error logs

Server logs remain JSON on stdout (`LOG_LEVEL=INFO` by default). Error records include
`extra.error_module`, `error_file`, `error_function`, `error_line`, and `traceback`.
The ordinary `name`/`function`/`line` fields identify the logging call; the `error_*`
fields identify where the exception originated. `extra.request_id` matches the
`X-Request-ID` response header for handled errors. Tracebacks omit local-variable
values. The benchmark HTTP adapter logs sanitized API error details, HTTP status,
request ID, and attempt number instead of reporting only an HTTP status.
Restart the app to load changes to logging.
